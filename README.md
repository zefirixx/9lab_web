## Описание задания
Научиться настраивать CI/CD pipeline, использовать GitHub Actions, запускать Docker-контейнеры в CI, автоматически запускать тесты PHPUnit и
выявлять ошибки через CI

---

## Как запустить проект

1. Клонировать репозиторий:
   ```bash
   git clone <ссылка на репозиторий>
   cd lab9
Запустить контейнеры:
```bash
docker-compose up -d --build
```
Открыть в браузере:
```http://localhost:8080```

Содержимое проекта:

```.github/workflows/ci.yml``` — файл настройки CI/CD pipeline GitHub Actions, который автоматически запускает Docker-контейнер и выполняет PHPUnit-тесты при каждом push в репозиторий

```Dockerfile``` — файл сборки Docker-образа PHP с установленным Composer и необходимыми расширениями для запуска приложения и тестов в CI-среде

```docker-compose.yml``` — файл конфигурации Docker Compose для запуска PHP-контейнера, который используется в CI/CD для выполнения тестов

```tests/``` — папка с тестами PHPUnit для проверки приложения

```tests/ExampleTest.php``` — базовый unit-тест для проверки корректной работы PHPUnit в проекте

```tests/ConferenceTest.php``` — unit-тесты для класса Conference, включающие проверку добавления данных, получения данных и использование mock-объектов PDO

```tests/ApiTest.php``` — тест HTTP-запроса через Guzzle, проверяющий доступность index.php через web-сервер

```www/Conference.php``` — основной класс бизнес-логики приложения (регистрация участников конференции, работа с PDO), используемый в unit-тестах и mock-тестах

```www/index.php``` — точка входа приложения, используемая для проверки HTTP-запросов в тесте ApiTest

```composer.json``` — файл зависимостей проекта, содержащий PHPUnit (dev-зависимость) и Guzzle для HTTP-тестирования

```vendor/``` — папка с автоматически установленными библиотеками Composer (PHPUnit, Guzzle и их зависимости)

```composer.lock``` — файл фиксации версий зависимостей проекта для обеспечения одинакового окружения в CI и локально

```.env.test``` — файл тестовой среды с переменными окружения, используемый для изоляции конфигурации при тестировании

Результат:
Настроен CI/CD pipeline с использованием GitHub Actions и Docker, который автоматически запускает PHPUnit-тесты при каждом push. Тесты выполняются в контейнере, а при ошибках сборка CI становится неуспешной.
